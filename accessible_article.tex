\section{What is this project?}

An experiment exploring accessible \LaTeX\ documents using the \LaTeX\ Tagging Project:

\begin{itemize}
\item \GreenText{Two document classes:} articles (\texttt{article}) and slides (\texttt{ltx-talk}).
\item \GreenText{Two flavors of each:} a minimal template (\texttt{minimal\_slides.tex}, \texttt{minimal\_article.tex}, $\sim$40 lines each, runnable in a minute) plus a fully annotated template (\texttt{accessible\_slides.tex}, \texttt{accessible\_article.tex}) that doubles as documentation.
\item \GreenText{Shows:} what's common to both, what's different.
\item \GreenText{Contains:} working examples with math, text, graphics, and tables.
\item \GreenText{Validation:} passes veraPDF (PDF/A-4 + UA-2). \RedText{Heads up:} popular validators (especially Ally) report \emph{false positives} under PDF/UA-2 -- not bugs in the templates. See ``Validator-specific notes'' below, and \texttt{VALIDATION.md} in the repo
\end{itemize}

\section{Figures}

When including a figure, you \RedText{must provide alt text} describing the image for screen readers. This is \emph{required} for accessibility compliance.\\

\noindent \fbox{%
  \ttfamily\small
  \textbackslash includegraphics[height=.4\textbackslash textheight,%
  \AltBox{alt=\{A capybara's head facing left\}}%
  ]\{capybara.jpg\}%
}

\subsection{Caption vs.\ alt text: they describe different things}

A common mistake is to put the same words in \texttt{\textbackslash caption\{...\}} and \texttt{alt=\{...\}}. They have \BlueText{different audiences}:

\begin{itemize}
\item \textbf{Caption} (\GreenText{visible to everyone}): an editorial title or annotation — what this figure is being used for in the surrounding argument. Sighted readers see the image \emph{and} the caption.
\item \textbf{Alt text} (\GreenText{read by screen readers in place of the image}): a literal description of what's in the image. A screen-reader user is hearing this \emph{instead of} seeing the picture, so it should stand alone.
\end{itemize}

\noindent In the example below the caption says why the figure is here (``a non-decorative illustration''), while the alt text describes what is actually depicted (``A capybara's head facing left''). For a purely decorative image, use \texttt{alt=\{\}} so the screen reader skips it.

\begin{figure}[htbp]
  \begin{center}
    \includegraphics[height=2.75in, alt={A capybara's head facing left}]{capybara.jpg}
  \end{center}
\caption{A capybara, included here as a non-decorative illustration of accessible figure markup.}
\end{figure}


\section{Tables}

When including a table, you \RedText{must specify which rows are headers}. Screen readers use this information to help users navigate table content.
Use \texttt{\textbackslash tagpdfsetup\{table/header-rows=\{...\}\}} \emph{before} the \texttt{tabular} environment:
\begin{itemize}
\item Use \texttt{\{1\}} for 1 header row
\item Use \texttt{\{1,2\}} for 2 header rows  
\item Use \texttt{\{1,2,3\}} for 3 header rows, etc.
\item \textbf{Validator note:} PAC can report \texttt{Table header cell has no associated subcells} even when headers are tagged correctly; the warning is still emitted by PAC 26.1.0 (March 2026). See PAC release notes at \urlu{https://pac.pdf-accessibility.org/en/resources/release-notes}.
\end{itemize}

\section{Code listings}

For code, use a real verbatim environment rather than \texttt{\textbackslash texttt} inside boxes; the block is then tagged as text and read aloud by screen readers.

\textbf{Tagging caveat.} As of TeX Live 2026 the two most popular code-listing packages, \texttt{listings} and \texttt{minted}, are \emph{not yet compatible} with the LaTeX tagging engine. \texttt{listings} is tracked at \urlu{https://github.com/latex3/tagging-project/issues/70}; \texttt{minted} hits the same problem because it loads \texttt{fvextra}, tracked at \urlu{https://github.com/latex3/tagging-project/issues/1060}. Both produce visually pleasing syntax-highlighted output but emit untagged graphical artifacts that screen readers skip.

\textbf{The working alternative today} is the \texttt{fancyvrb} package -- specifically the \texttt{Verbatim} environment and the \texttt{\textbackslash VerbatimInput} command, which is what \texttt{ltx-talk}'s own demos use. No syntax highlighting (yet), but the code is tagged and screen-readable, which is the accessibility-first tradeoff:

\VerbatimInput[fontsize=\small, frame=single, numbers=left]{examples/log_returns.py}

\noindent When \texttt{listings}/\texttt{minted} become tagging-compatible upstream, you can switch back; the configuration block near the top of this file shows the WCAG-AA-safe color palette to use.


\section{Common pitfalls}
  \begin{itemize}
  \item \RedText{Confusing PDF tagging with PDF bookmarks}
    \begin{itemize}
    \item \texttt{tagging=on} creates structure tree for \GreenText{screen readers} (required for accessibility!)
    \item PDF bookmarks (navigation outline in left pane) are \GreenText{separate and optional}
    \item Bookmarks do NOT generate automatically from \texttt{tagging=on}
    \item For articles: use \texttt{\textbackslash tableofcontents} or the \texttt{bookmark} package
    \item For slides: See custom bookmark code in \texttt{accessible\_slides.tex} preamble (Part 2)
    \end{itemize}
    
  \item \RedText{Forgetting alt text for images}
    \begin{itemize}
    \item Every \texttt{\textbackslash includegraphics} needs an \texttt{alt=\{...\}} parameter
    \item For purely decorative images, use empty alt text: \texttt{alt=\{\}}
    \end{itemize}
    
  \item \RedText{Not specifying table header rows}
    \begin{itemize}
    \item Add \texttt{\textbackslash tagpdfsetup\{table/header-rows=\{...\}\}} before each table
    \item Use \texttt{\{1\}} for 1 header row, \texttt{\{1,2\}} for 2 header rows, etc.
    \end{itemize}
    
  \item \RedText{Insufficient color contrast}
    \begin{itemize}
    \item WCAG 2.1 requires 4.5:1 contrast ratio for normal text
    \item Avoid light colors: \texttt{yellow}, \texttt{cyan} fail contrast requirements
    \item Darken \texttt{red} and \texttt{green}: use \texttt{red!80!black}, \texttt{green!40!black}
    \item Standard \texttt{blue} is fine and meets WCAG requirements
    \item Test with a contrast checker: \urlu{https://webaim.org/resources/contrastchecker/}
    \end{itemize}

  \item \RedText{Using the wrong compiler}
    \begin{itemize}
    \item Make sure your editor is set to use \GreenText{LuaLaTeX}, not \RedText{pdfLaTeX}
    \end{itemize}
    
  \item \RedText{Old TeX distribution}
    \begin{itemize}
    \item TeX Live 2022 or earlier won't work
    \item Update packages using TeX Live Manager (Windows) or TeX Live Utility (Mac)
    \end{itemize}
    
  \end{itemize}

  \end{itemize}

\section{Validation workflow: use multiple checkers}

\begin{itemize}
\item No single checker catches everything.
\item Accessibility usability checks and strict PDF conformance checks are not identical.
\item A practical workflow is to run more than one checker and compare findings.
\end{itemize}

\noindent \textbf{Checkers used so far:} Ally (the accessibility checker built into bCourses), veraPDF (open-source PDF conformance validator, \urlu{https://verapdf.org/}), PAC (PDF Accessibility Checker, \urlu{https://pac.pdf-accessibility.org/}), and Acrobat.

\section{Optional validator cleanup step: \texttt{strip\_af.py}}

\begin{itemize}
\item The metadata settings produce a fully tagged PDF that passes veraPDF (PDF/A-4 + UA-2). \textbf{Heads up:} Ally and some other validators currently report false errors under PDF/UA-2 (math read as ``images''; legacy PDF-1.x title check). See ``Validator-specific notes'' below for the full list.
\item Stricter checkers (e.g., \RedText{veraPDF}) may still complain about /AF or embedded-file structures.
\item Optional strict-archival cleanup command:
\end{itemize}

\begin{quote}\ttfamily
python strip\_af.py build/yourfile.pdf
\end{quote}

\begin{itemize}
\item Then validate \texttt{build/yourfile.pdf} with \texttt{veraPDF}.
\item Prerequisite for the script: \texttt{python -m pip install pikepdf}
\end{itemize}

\section{Validator-specific notes}

No single accessibility checker catches everything. Treat one-tool warnings as signals to investigate, not as proof of source errors. The items below are known false positives that can be ignored. See \texttt{VALIDATION.md} in the repo for the full per-tool status.

\subsection{Per-tool quirks (also present under UA-1)}

\begin{itemize}
\item \textbf{Acrobat: ``Lbl and LBody -- Failed.''} Raised on tagged lists, figure captions, table captions, and section numbers even when the \texttt{<Lbl>} tag is structurally correct. Known Acrobat checker bug. Reference: \urlu{https://tex.stackexchange.com/a/709655/2388}.
\item \textbf{PAC: ``Table header cell has no associated subcells.''} Reported even when \texttt{\textbackslash tagpdfsetup\{table/header-rows=\{\ldots\}\}} is set correctly. Still present in PAC 26.1.0 (March 2026). Track: \urlu{https://pac.pdf-accessibility.org/en/resources/release-notes}.
\end{itemize}

\subsection{UA-2 / PDF 2.0 checker-coverage gaps (new since template v2.0)}

\noindent Template v2.0 upgraded the targets from PDF/UA-1 + PDF/A-2 (PDF~1.7) to \BlueText{PDF/UA-2 + PDF/A-4} (PDF~2.0). UA-2 is the newer, stricter, more accessible standard, but most validators were written for UA-1 and haven't fully caught up. The reports below look like errors; they're \GreenText{checker lag, not template regressions}. The meaningful UA-2 conformance check today is veraPDF, which passes both example PDFs.

\begin{itemize}
\item \textbf{PAC validates against PDF/UA-1, not UA-2.} At open, PAC warns it ``currently fully supports documents up to and including PDF~1.7.'' The test report itself shows \texttt{Standard: PDF/UA-1} --- PAC has no UA-2 checker and silently falls back. Expect a non-trivial failure count on the test report because UA-2 introduces structure elements and role names the UA-1 checker doesn't recognize. These are not real conformance bugs.
\item \textbf{Ally: ``Image without a description'' on every inline equation.} Ally doesn't yet parse UA-2 MathML content tags, so it reports the rendered math as an untagged image. In this article: the \texttt{\$\textbackslash mathit\{math\}\$} example and the column-header math (\texttt{\$DF\_\{pay\}\$}, \texttt{\$T\_\{expiry\}\$}, \texttt{\$\textbackslash Delta\$}) in the example table. The math \emph{is} tagged as MathML; Ally hasn't learned to read it.
\item \textbf{Ally: ``The PDF does not have a title.''} Ally checks the legacy PDF~1.x \texttt{/Title} key, which PDF~2.0 deprecates in favor of XMP \texttt{dc:title}. \LaTeX\ writes XMP; veraPDF accepts it; Ally has not caught up.
\end{itemize}
